## 函数骨架核对方法

只依赖 `metaData.params` 会出错：部分链表、树题描述的是判题器的序列化输入，例如链表相交题的 `intersectVal`、`skipA` 和 `skipB`，而这些不是 Python 方法的参数。

因此实际骨架使用官方 `codeSnippets` 中 Python3 的 `class` / `def` 声明，并另写空方法体。来源快照只保存这些声明。已逐题核对全部 100 个骨架，包括：

- 160 的参数是 `headA, headB`；141 / 142 没有 `pos` 参数。
- 138 使用带 `random` 指针的 `Node`；236 的 `root, p, q` 都是树节点。
- 146、208、155、295 保留各自的设计类及全部方法，分别为 `LRUCache`、`Trie`、`MinStack`、`MedianFinder`。
- 本地练习所需的 `ListNode`、`TreeNode` 和 `Node` 辅助类型独立编写。所有待实现方法抛出 `NotImplementedError`，不会把空实现显示成已完成答案。

离线验证用 Python AST 比较官方声明与本站骨架的类、方法、参数、默认值、参数注解，并编译全部 100 个骨架。此检查不向力扣提交答案。

## 本地复现

在仓库根目录执行：

```sh
python scripts/verify-hot100.py --run-references
npm exec -- vitest run tests/hot100Catalog.test.ts
```

第一个命令先核对 100 题索引与接口，再把各包的本站参考文件复制为 `output/hot100-checks-*/lc-题号/solution.py`，执行该包的原创测试。临时结果留在 Git 忽略的 `output` 中。这个开发验证脚本只运行仓库作者的参考代码，不接收网站用户上传的代码，也没有接入远程执行服务。

学习者下载自己的代码时使用文件名 `solution.py`，与该题下载的 `test_solution.py` 放在同一个目录，执行：

```sh
python -m unittest -v test_solution.py
```

需要重新核验官方索引时执行：

```sh
node scripts/fetch-hot100-index.mjs
```

如果本机访问官方站点需要用户已有的可信 HTTP 代理，可仅为当前终端设置 `HOT100_HTTP_PROXY`，例如 `http://127.0.0.1:YOUR_PORT`。脚本不会读取浏览器登录态或凭据，遇到非 200 响应、来源结构变化或非 100 题清单会停止。刷新只更新来源快照，不自动改写本站原创讲解或代码；审查快照后再更新任务索引，并重跑验证。
